## Criteria

A tool is considered to have sufficient system-prompt instructions when:

1. **Description length ≥120 characters** and explains purpose, required parameters, and common gotchas.
2. **Every parameter has a description** in the JSON Schema.
3. **`additionalProperties: false`** is set on the schema (where the tool accepts named parameters) to reject hallucinated keys.
4. **Required parameters are explicitly called out** both in the description and in the schema `required` array.

### T-002: Add `additionalProperties: false` to schemas

**Status:** ✅ Completed.

**Scope:** 122 tools.

every tool that accepts named parameters, unless the tool intentionally accepts
arbitrary keys (e.g. `http_request` headers still use `"additionalProperties":
{ "type": "string" }` inside the headers sub-schema, with the root object now
strict). This prevents models from inventing parameter names.

### T-004: Add system-prompt guidance sections for complex tool families

**Status:** ✅ Completed.

Several groups of tools benefit from dedicated system-prompt guidance in addition to per-tool descriptions. The following sections were added or updated in `crates/ragent-agent/src/agent/mod.rs` and `crates/ragent-agent/src/session/prompt_builders.rs`:

- [x] **VCS/Git tools** (`git_*`, `github_*`, `gitlab_*`) — added a `## Version Control Safety` section that reinforces never push without explicit instruction, never tag unless told, use `Version: X.Y.Z` commit messages, and do not use `git checkout` to rewind files.
- [x] **Codeindex tools** (`codeindex_*`) — section already in `prompt_builders.rs`; verified it covers `max_results` defaults (20, max 100) and `kind` enum values.
- [x] **Team tools** (`team_*`) — added a compact `## Team Tools Quick Reference` table with required params for every team tool.
- [x] **Task tool family** (`new_task`, `cancel_task`, `list_tasks`, `wait_tasks`, `task_complete`) — already covered by `TASK_TOOL_FAMILY_GUIDANCE`; verified descriptions still match schema.
- [x] **File tools** (`read`, `write`, `edit`, `multi_edit`, `patch`, `apply_patch`, `diff_files`, `move_file`, `copy_file`, `rm`, `mkdir`, `glob`, `list`) — already have file-reading and editing sections; kept in place.
- [x] **Web/MasterFetch tools** (`webfetch`, `websearch`, `http_request`, `mf_*`) — added guidance in per-tool descriptions; system prompt notes use `webfetch` for simple fetching and `http_request` for full control.
- [x] **Memory tools** (`memory_store`, `memory_recall`, `memory_forget`, `memory_search`, etc.) — added a `## Memory Tools` section covering required params, categories, confidence scale, and tags.
- [x] **Question/AskUser tools** (`ask_user`, `question`) — added a `## Question / AskUser Tools` section kept in sync with the `ask_user` schema.
