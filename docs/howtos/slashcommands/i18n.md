# /i18n

> UI language: /i18n on|off|status|list|<locale> | /i18n help

## Overview

`/i18n` controls UI internationalisation. When enabled, user-facing strings
(the status bar, the `/help` header and the catalogue footer) are rendered
from a locale message catalog; any key missing from the catalog falls back
to the compiled English text.

Catalogs are JSON files named after the locale:

- `<project>/.ragent/locales/<locale>.json` (project, probed first)
- `~/.config/ragent/locales/<locale>.json` (user)

A locale tag such as `fr_FR.UTF-8` is probed as `fr_fr` and then `fr`.

The state persists in the `i18n` section of `ragent.json`
(`i18n.enabled`, `i18n.locale`, default `false` / `en`). With no `i18n`
section, a non-English ambient `LANG` that has an installed catalog
enables translation automatically.

## Syntax

```
/i18n              Show the effective state (same as /i18n status)
/i18n on           Enable translated strings and persist it
/i18n off          Disable translation and persist it
/i18n <locale>     Enable translation with the given locale and persist both
/i18n status       Show state, locale, and catalog availability
/i18n list         List installed locale catalogs
/i18n help         Print the help table
```

`--help` and `-h` are accepted as aliases of `help`. Subcommands are
matched case-insensitively; any other token is treated as a locale tag.

## Options / Subcommands

| Form | Description |
| ---- | ----------- |
| `on` | Apply `enabled = true` in-process, persist `i18n.enabled: true` via `ragent_config::i18n::persist`, then invalidate the session processor's config cache. The locale is unchanged. |
| `off` | Same as `on` with `enabled = false`; the compiled English text is served. |
| `<locale>` | Enable translation and persist both `i18n.enabled: true` and `i18n.locale: <locale>` (e.g. `/i18n fr`, `/i18n de_DE.UTF-8`). |
| `status` | Report the effective on/off state, effective locale, whether a catalog is loaded, whether one exists for the locale, and the persisted config value. Bare `/i18n` does the same. |
| `list` | Enumerate the `*.json` catalogs in both locale directories with their paths, or `(none installed; English is always available)`. |
| `help` | Print the help table. Note: the help text says bare `/i18n` shows help, but the dispatcher routes bare `/i18n` to `status`. |

If persisting fails (config file not writable), the change still applies
for the live session and the status line shows `i18n: unsaved`.

## Examples

```
/i18n fr
```

Enables translation with the French catalog and writes
`"i18n": { "enabled": true, "locale": "fr" }` to the active config source.

```
/i18n off
```

Returns to English and persists `i18n.enabled: false`.

```
/i18n list
```

Shows which locale catalogs are installed.

## Output

`on`/`off`/`<locale>` confirm the change:

```
✅ UI internationalisation enabled (locale `fr`).
Catalog loaded: true
```

A failed persist surfaces as a warning:

```
⚠ UI internationalisation enabled for this session, but saving the config failed: <e> (unsaved).
```

`status` prints `UI internationalisation`, `Effective locale`,
`Catalog loaded`, `Catalog available` and `Persisted config` lines. If no
catalog is found for an enabled non-English locale, a warning is logged and
English is used.
