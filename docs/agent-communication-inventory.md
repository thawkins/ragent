## 10. Message Flow Summary

### Sub-agent flow
```
User / LLM -> new_tool tool -> TaskManager::spawn_background/sync
  -> run_subagent -> SessionProcessor::process_message (child session)
  -> publishes SubagentStart/Complete/Failed/Cancelled on EventBus
  -> TUI / HTTP SSE / wait_tasks consume events
```

### Teammate flow
```
Lead tool call (team_create / team_spawn)
  -> TeamStore writes config.json
  -> TeamManager::spawn_teammate_internal
      -> creates child session
      -> starts SessionProcessor::process_message in tokio task
      -> starts mailbox poll loop
      -> publishes TeammateSpawned
  -> Teammate runs its own agent loop
      -> first action must be team_read_messages (drains mailbox)
      -> uses team_task_claim / team_task_complete / team_message / team_idle etc.
  -> Mailbox writes go to <team_dir>/mailboxes/<agent_id>.jsonl
  -> Poll loop drains unread and publishes TeammateMessage / TeammateP2PMessage / TeammateIdle
  -> TUI / HTTP SSE display events
```

### Orchestrator flow
```
HTTP / programmatic -> Coordinator::start_job_sync/async
  -> match_agents -> Router::send -> AgentEntry mailbox (InProcessRouter) or HTTP endpoint (HttpRouter)
  -> agent responder returns result
  -> Coordinator aggregates/concatenates and returns / publishes JobEvent
```

### Permission / auto-approval flow
```
Tool call -> check_permission_with_prompt
  -> hardwired auto-approved set includes all `team_*`, `*_task`, `task_complete`, `list_tasks`, `wait_tasks`, codeindex tools
  -> otherwise PermissionChecker / user prompt / auto-approve / YOLO
  -> result Allow/Deny/Ask
```
