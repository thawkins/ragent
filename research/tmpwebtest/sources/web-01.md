**Rust** is a [general-purpose][227] [programming language][228] which emphasizes [performance][229], [type
safety][230], [concurrency][231], and [memory safety][232].

Rust supports multiple [programming paradigms][233]. It was influenced by ideas from [functional programming][234],
including [immutability][235], [higher-order functions][236], [algebraic data types][237], and [pattern matching][238].
It also supports [object-oriented programming][239] via structs, [enums][240], traits, and methods. Rust enforces memory
safety (i.e., that all [references][241] point to valid memory) without a conventional [garbage collector][242];
instead, memory safety errors and [data races][243] are prevented by the "borrow checker", which tracks the [object
lifetime][244] of references [at compile time][245].

Software developer Graydon Hoare created Rust in 2006 while working at [Mozilla][246], which officially sponsored the
project in 2009. The first stable release, Rust 1.0, was published in May 2015. The project has been sponsored by the
[Rust Foundation][247] since February 2021.

Rust has been adopted by many software projects, especially [web services][248] and [system software][249]. It has been
studied academically and has a growing community of developers.

## History

[[edit][250]]

### 2006–2009: Early years

[[edit][251]]
Mozilla Foundation headquarters, 650 Castro Street in [Mountain View, California][252], June 2009

Rust began as a personal project by [Mozilla][253] employee Graydon Hoare in 2006. According to MIT Technology Review,
he started the project due to his frustration with a broken elevator in his apartment building whose software had
crashed,^{[[20]][254]} and named the language after the [group of fungi of the same name][255] that is "over-engineered
for survival".^{[[20]][256]} During the time period between 2006 and 2009, Rust was not publicized to others at Mozilla
and was written in Hoare's free time;^{[[21]][257]}^{: 7:50 } Hoare began speaking about the language around 2009 after
a small group at Mozilla became interested in the project.^{[[22]][258]} Hoare cited languages from the 1970s, 1980s,
and 1990s as influences — including [CLU][259], [BETA][260], [Mesa][261], NIL,^{[[note 4]][262]} [Erlang][263],
[Newsqueak][264], [Napier][265], [Hermes][266], [Sather][267], [Alef][268], and [Limbo][269].^{[[22]][270]} He described
the language as "technology from the past come to save the future from itself."^{[[21]][271]}^{: 8:17 }^{[[22]][272]}
Early Rust developer Manish Goregaokar similarly described Rust as being based on "mostly decades-old
research."^{[[20]][273]}

During the early years, the Rust [compiler][274] was written in about 38,000 lines of [OCaml][275].^{[[21]][276]}^{:
15:34 }^{[[23]][277]} Early Rust contained several features no longer present today, including explicit [object-oriented
programming][278] via an `obj` keyword^{[[21]][279]}^{: 10:08 } and a [typestates][280] system for variable state
changes, such as going from uninitialized to initialized.^{[[21]][281]}^{: 13:12 }

### 2009–2012: Mozilla sponsorship

[[edit][282]]

Mozilla officially sponsored the Rust project in 2009.^{[[20]][283]} [Brendan Eich][284] and other executives, intrigued
by the possibility of using Rust for a safe [web browser][285] [engine][286], placed engineers on the project including
Patrick Walton, Niko Matsakis, Felix Klock, and Manish Goregaokar.^{[[20]][287]} A conference room taken by the project
developers was dubbed "the nerd cave," with a sign placed outside the door.^{[[20]][288]}

During this time period, work had shifted from the initial OCaml compiler to a [self-hosting compiler][289] (i.e.,
written in Rust) targeting [LLVM][290].^{[[24]][291]}^{[[note 5]][292]} The ownership system was in place by
2010.^{[[20]][293]} The Rust logo was developed in 2011 based on a bicycle chainring.^{[[26]][294]}

Rust 0.1 became the first public release on January 20, 2012^{[[27]][295]} for Windows, Linux, and MacOS.^{[[28]][296]}
The early 2010s witnessed increasing involvement from full-time engineers at Mozilla and open source volunteers outside
Mozilla.^{[[20]][297]}

### 2012–2015: Evolution

[[edit][298]]

The years from 2012 to 2015 were marked by substantial changes to the Rust [type system][299].^{[[21]][300]}^{: 18:36
}^{[[20]][301]} Memory management through the ownership system was gradually consolidated and expanded. By 2013, the
[garbage collector][302] was rarely used, and was removed in favor of the ownership system.^{[[20]][303]} Other features
were removed in order to simplify the language, including typestates, the `pure` keyword,^{[[29]][304]} various
specialized pointer types, and syntax support for [channels][305].^{[[21]][306]}^{: 22:32 }

According to Steve Klabnik, Rust was influenced during this period by developers coming from [C++][307] (e.g., low-level
performance of features), [scripting languages][308] (e.g., Cargo and package management), and [functional
programming][309] (e.g., type systems development).^{[[21]][310]}^{: 30:50 }

Graydon Hoare stepped down from Rust in 2013.^{[[20]][311]} After Hoare's departure, it evolved organically under a
federated governance structure, with a "core team" of initially six people,^{[[21]][312]}^{: 21:45 } and around 30-40
developers total across various other teams.^{[[21]][313]}^{: 22:22 } A [Request for Comments][314] (RFC) process for
new language features was added in March 2014.^{[[21]][315]}^{: 33:47 } The core team would grow to nine people by
2016^{[[21]][316]}^{: 21:45 } with over 1600 RFCs.^{[[21]][317]}^{: 34:08 }

According to Andrew Binstock for [Dr. Dobb's Journal][318] in January 2014, while Rust was "widely viewed as a
remarkably elegant language", adoption slowed because it radically changed from version to version.^{[[30]][319]} Rust
development at this time focused on finalizing features for version 1.0 so that it could begin promising [backward
compatibility][320].^{[[21]][321]}^{: 41:26 }

Six years after Mozilla's sponsorship, Rust 1.0 was published and became the first [stable release][322] on May 15,
2015.^{[[20]][323]} A year later, the Rust compiler had accumulated over 1,400 contributors, and there were over 5,000
third-party libraries published on the Rust package management website Crates.io.^{[[21]][324]}^{: 43:15 }

### 2015–2020: Servo and early adoption

[[edit][325]]
Early homepage of Mozilla's [Servo browser engine][326]

The development of the [Servo browser engine][327] continued in parallel with Rust, jointly funded by Mozilla and
[Samsung][328].^{[[31]][329]} The teams behind the two projects worked in close collaboration; new features in Rust were
tested out by the Servo team, and new features in Servo were used to give feedback back to the Rust
team.^{[[21]][330]}^{: 5:41 } The first version of Servo was released in 2016.^{[[20]][331]} The [Firefox][332] web
browser shipped with Rust code as of 2016 (version 45),^{[[21]][333]}^{: 53:30 }^{[[32]][334]} but components of Servo
did not appear in Firefox until September 2017 (version 57) as part of the [Gecko][335] and [Quantum][336]
projects.^{[[33]][337]}

Improvements were made to the Rust toolchain ecosystem during the years following 1.0 including [Rustfmt][338],
[integrated development environment][339] integration,^{[[21]][340]}^{: 44:56 } and a regular compiler testing and
release cycle.^{[[21]][341]}^{: 46:48 } Rust's community gained a [code of conduct][342] and an [IRC][343] chat for
discussion.^{[[21]][344]}^{: 50:36 }

The earliest known adoption outside of Mozilla was by individual projects at Samsung, [Facebook][345] (now [Meta
Platforms][346]), [Dropbox][347], and Tilde, Inc., the company behind [ember.js][348].^{[[21]][349]}^{: 55:44
}^{[[20]][350]} [Amazon Web Services][351] followed in 2020.^{[[20]][352]} Engineers cited performance, lack of a
garbage collector, safety, and pleasantness of working in the language as reasons for the adoption. Amazon developers
cited a finding by Portuguese researchers that Rust code used [less energy][353] compared to similar code written in
[Java][354].^{[[20]][355]}^{[[34]][356]}

### 2020–present: Mozilla layoffs and Rust Foundation

[[edit][357]]

In August 2020, Mozilla laid off 250 of its 1,000 employees worldwide, as part of a corporate restructuring caused by
the [COVID-19 pandemic][358].^{[[35]][359]}^{[[36]][360]} The team behind Servo was disbanded. The event raised concerns
about the future of Rust.^{[[37]][361]} In the following week, the Rust Core Team acknowledged the severe impact of the
layoffs and announced that plans for a Rust foundation were underway. The first goal of the foundation would be to take
ownership of all [trademarks][362] and [domain names][363] and to take financial responsibility for their
costs.^{[[38]][364]}

On February 8, 2021, the formation of the [Rust Foundation][365] was announced by five founding companies: [Amazon Web
Services][366], [Google][367], [Huawei][368], [Microsoft][369], and [Mozilla][370].^{[[39]][371]}^{[[40]][372]} The
foundation would provide financial support for Rust developers in the form of grants and server funding.^{[[20]][373]}
In a blog post published on April 6, 2021, Google announced support for Rust within the [Android Open Source
Project][374] as an alternative to C/C++.^{[[41]][375]}

On November 22, 2021, the Moderation Team, which was responsible for enforcing the community code of conduct, announced
their resignation "in protest of the Core Team placing themselves unaccountable to anyone but themselves".^{[[42]][376]}
In May 2022, members of the Rust leadership council posted a public response to the incident.^{[[43]][377]}

The Rust Foundation posted a draft for a new trademark policy on April 6, 2023, which resulted in widespread negative
reactions from Rust users and contributors.^{[[44]][378]} The trademark policy included rules for how the Rust logo and
name could be used.^{[[44]][379]}

## Syntax and features

[[edit][380]]
Main article: [Rust syntax][381]

Rust's [syntax][382] is similar to that of [C][383] and [C++][384],^{[[45]][385]}^{[[46]][386]} although many of its
features were influenced by [functional programming][387] languages such as [OCaml][388].^{[[47]][389]} Hoare has
described Rust as targeted at frustrated C++ developers.^{[[22]][390]}

### Hello World program

[[edit][391]]

Below is a ["Hello, World!" program][392] in Rust. The `fn` keyword denotes a [function][393], and the `println!`
[macro][394] (see [§ Macros][395]) prints the message to [standard output][396].^{[[48]][397]} [Statements][398] in Rust
are separated by [semicolons][399].

fn main() {
    println!("Hello, World!");
}

### Variables

[[edit][400]]

[Variables][401] in Rust are defined through the `let` keyword.^{[[49]][402]} The example below assigns a value to the
variable with name `foo` of type `i32` and outputs its value; the type annotation `: i32` can be omitted.

fn main() {
    let foo: i32 = 10;
    println!("The value of foo is {foo}");
}

Variables are [immutable][403] by default, unless the `mut` keyword is added.^{[[50]][404]} The following example uses
`//`, which denotes the start of a [comment][405].^{[[51]][406]}

fn main() {
    // This code would not compile without adding "mut".
    let mut foo = 10;
    println!("The value of foo is {foo}");
    foo = 20;
    println!("The value of foo is {foo}");
}

Multiple `let` expressions can define multiple variables with the same name, known as [variable shadowing][407].
Variable shadowing allows transforming variables without having to name the variables differently.^{[[52]][408]} The
example below declares a new variable with the same name that is double the original value:

fn main() {
    let foo = 10;
    // This will output "The value of foo is 10"
    println!("The value of foo is {foo}");
    let foo = foo * 2;
    // This will output "The value of foo is 20"
    println!("The value of foo is {foo}");
}

Variable shadowing is also possible for values of different types. For example, going from a string to its length:

fn main() {
    let letters = "abc";
    let letters = letters.len();
}

### Block expressions and control flow

[[edit][409]]

A block expression is delimited by [curly brackets][410]. When the last expression inside a block does not end with a
semicolon, the block evaluates to the value of that trailing expression:^{[[53]][411]}

fn main() {
    let x = {
        println!("this is inside the block");
        1 + 2
    };
    println!("1 + 2 = {x}");
}

Trailing expressions of function bodies are used as the return value:^{[[54]][412]}

fn add_two(x: i32) -> i32 {
    x + 2
}

#### `if` expressions

[[edit][413]]

An `if` [conditional expression][414] executes code based on whether the given value is `true`. `else` can be used for
when the value evaluates to `false`, and `else if` can be used for combining multiple expressions.^{[[55]][415]}

fn main() {
    let x = 10;
    if x > 5 {
        println!("value is greater than five");
    }

    if x % 7 == 0 {
        println!("value is divisible by 7");
    } else if x % 5 == 0 {
        println!("value is divisible by 5");
    } else {
        println!("value is not divisible by 7 or 5");
    }
}

`if` and `else` blocks can evaluate to a value, which can then be assigned to a variable:^{[[55]][416]}

fn main() {
    let x = 10;
    let new_x = if x % 2 == 0 { x / 2 } else { 3 * x + 1 };
    println!("{new_x}");
}

#### `while` loops

[[edit][417]]

`[while][418]` can be used to repeat a block of code while a condition is met.^{[[56]][419]}

fn main() {
    // Iterate over all integers from 4 to 10
    let mut value = 4;
    while value <= 10 {
         println!("value = {value}");
         value += 1;
    }
}

#### `for` loops and iterators

[[edit][420]]

[For loops][421] in Rust loop over elements of a collection.^{[[57]][422]} `for` expressions work over any
[iterator][423] type.

fn main() {
    // Using `for` with range syntax for the same functionality as above
    // The syntax 4..=10 means the range from 4 to 10, up to and including 10.
    for value in 4..=10 {
        println!("value = {value}");
    }
}

In the above code, `4..=10` is a value of type `Range` which implements the `Iterator` trait. The code within the curly
braces is applied to each element returned by the iterator.

Iterators can be combined with functions over iterators like `map`, `filter`, and `sum`. For example, the following adds
up all numbers between 1 and 100 that are multiples of 3:

(1..=100).filter(|x| x % 3 == 0).sum()

#### `loop` and `break` statements

[[edit][424]]

More generally, the `loop` keyword allows repeating a portion of code until a `break` occurs. `break` may optionally
exit the loop with a value. In the case of nested loops, labels denoted by `'label_name` can be used to break an outer
loop rather than the innermost loop.^{[[58]][425]}

fn main() {
    let value = 456;
    let mut x = 1;
    let y = loop {
        x *= 10;
        if x > value {
            break x / 10;
        }
    };
    println!("largest power of ten that is smaller than or equal to value: {y}");

    let mut up = 1;
    'outer: loop {
        let mut down = 120;
        loop {
            if up > 100 {
                break 'outer;
            }

            if down < 4 {
                break;
            }

            down /= 2;
            up += 1;
            println!("up: {up}, down: {down}");
        }
        up *= 2;
    }
}

### Pattern matching

[[edit][426]]

The `match` and `if let` expressions can be used for [pattern matching][427]. For example, `match` can be used to double
an optional integer value if present, and return zero otherwise:^{[[59]][428]}

fn double(x: Option<u64>) -> u64 {
    match x {
        Some(y) => y * 2,
        None => 0,
    }
}

Equivalently, this can be written with `if let` and `else`:

fn double(x: Option<u64>) -> u64 {
    if let Some(y) = x {
        y * 2
    } else {
        0
    }
}

### Types

[[edit][429]]

Rust is [strongly typed][430] and [statically typed][431], meaning that the types of all variables must be known at
compilation time. Assigning a value of a particular type to a differently typed variable causes a [compilation
error][432]. [Type inference][433] is used to determine the type of variables if unspecified.^{[[60]][434]}

The type `()`, called the "unit type" in Rust, is a concrete type that has exactly one value. It occupies no memory (as
it represents the absence of value). All functions that do not have an indicated return type implicitly return `()`. It
is similar to `void` in other C-style languages; however, `void` denotes the absence of a type and cannot have any
value.

The default integer type is `i32`, and the default [floating point][435] type is `f64`. If the type of a [literal][436]
number is not explicitly provided, it is either inferred from the context or the default type is used.^{[[61]][437]}

#### Primitive types

[[edit][438]]

[Integer types][439] in Rust are named based on the [signedness][440] and the number of bits the type takes. For
example, `i32` is a signed integer that takes 32 bits of storage, whereas `u8` is unsigned and only takes 8 bits of
storage. `isize` and `usize` take storage depending on the [memory address bus width][441] of the compilation target.
For example, when building for [32-bit targets][442], both types will take up 32 bits of
space.^{[[62]][443]}^{[[63]][444]}

By default, integer literals are in base-10, but different [radices][445] are supported with prefixes, for example,
`0b11` for [binary numbers][446], `0o567` for [octals][447], and `0xDB` for [hexadecimals][448]. By default, integer
literals default to `i32` as its type. Suffixes such as `4u32` can be used to explicitly set the type of a
literal.^{[[64]][449]} Byte literals such as `b'X'` are available to represent the [ASCII][450] value (as a `u8`) of a
specific character.^{[[65]][451]}

The [Boolean type][452] is referred to as `bool` which can take a value of either `true` or `false`. A `char` takes up
32 bits of space and represents a Unicode scalar value:^{[[66]][453]} a [Unicode codepoint][454] that is not a
[surrogate][455].^{[[67]][456]} [IEEE 754][457] floating point numbers are supported with `f32` for [single precision
floats][458] and `f64` for [double precision floats][459].^{[[68]][460]}

#### Compound types

[[edit][461]]

Compound types can contain multiple values. Tuples are fixed-size lists that can contain values whose types can be
different. Arrays are fixed-size lists whose values are of the same type. Expressions of the tuple and array types can
be written through listing the values, and can be accessed with `.index` (with tuples) or `[index]` (with
arrays):^{[[69]][462]}

let tuple: (u32, bool) = (3, true);
let array: [i8; 5] = [1, 2, 3, 4, 5];
let value = tuple.1; // true
let value = array[2]; // 3

Arrays can also be constructed through copying a single value a number of times:^{[[70]][463]}

let array2: [char; 10] = [' '; 10];

### Ownership and references

[[edit][464]]

Rust's ownership system consists of rules that ensure memory safety without using a garbage collector. At compile time,
each value must be attached to a variable called the owner of that value, and every value must have exactly one
owner.^{[[71]][465]} Values are moved between different owners through assignment or passing a value as a function
parameter. Values can also be borrowed, meaning they are temporarily passed to a different function before being
returned to the owner.^{[[72]][466]} With these rules, Rust can prevent the creation and use of [dangling
pointers][467]:^{[[72]][468]}^{[[73]][469]}

fn print_string(s: String) {
    println!("{}", s);
}

fn main() {
    let s = String::from("Hello, World");
    print_string(s); // s consumed by print_string
    // s has been moved, so cannot be used any more
    // another print_string(s); would result in a compile error
}

The function `print_string` takes ownership over the `String` value passed in; Alternatively, `&` can be used to
indicate a [reference][470] type (in `&String`) and to create a reference (in `&s`):^{[[74]][471]}

fn print_string(s: &String) {
    println!("{}", s);
}

fn main() {
    let s = String::from("Hello, World");
    print_string(&s); // s borrowed by print_string
    print_string(&s); // s has not been consumed; we can call the function many times
}

Because of these ownership rules, Rust types are known as [affine types][472], meaning each value may be used at most
once. This enforces a form of [software fault isolation][473] as the owner of a value is solely responsible for its
correctness and deallocation.^{[[75]][474]}

When a value goes out of scope, it is dropped by running its [destructor][475]. The destructor may be programmatically
defined through implementing the `Drop` [trait][476]. This helps manage resources such as file handles, network sockets,
and [locks][477], since when objects are dropped, the resources associated with them are closed or released
automatically.^{[[76]][478]}

#### Lifetimes

[[edit][479]]

[Object lifetime][480] refers to the period of time during which a reference is valid; that is, the time between the
object creation and destruction.^{[[77]][481]} These lifetimes are implicitly associated with all Rust reference types.
While often inferred, they can also be indicated explicitly with named lifetime parameters (often denoted `'a`, `'b`,
and so on).^{[[78]][482]}

A value's lifetime in Rust is inferred from the set of locations in the source code (i.e., function, line, and column
numbers) for which a variable is valid.^{[[79]][483]} For example, a reference to a local variable has a lifetime from
the expression it is declared in up until the last use of it.^{[[79]][484]}

fn main() {
    let mut x = 5;            // ------------------+- Lifetime 'a
                              //                   |
    let r = &x;               // -+-- Lifetime 'b  |
                              //  |                |
    println!("r: {}", r);     // -+                |
    // Since r is no longer used,                  |
    // its lifetime ends                           |
    let r2 = &mut x;          // -+-- Lifetime 'c  |
}                             // ------------------+

The borrow checker in the Rust compiler then enforces that references are only used in the locations of the source code
where the associated lifetime is valid.^{[[80]][485]}^{[[81]][486]} In the example above, storing a reference to
variable `x` in `r` is valid, as variable `x` has a longer lifetime (`'a`) than variable `r` (`'b`). However, when `x`
has a shorter lifetime, the borrow checker would reject the program:

fn main() {
    let r;                    // ------------------+- Lifetime 'a
                              //                   |
    {                         //                   |
        let x = 5;            // -+-- Lifetime 'b  |
        r = &x; // ERROR: x does  |                |
    }           // not live long -|                |
                // enough                          |
    println!("r: {}", r);     //                   |
}                             // ------------------+

Since the lifetime of the referenced variable (`'b`) is shorter than the lifetime of the variable holding the reference
(`'a`), the borrow checker errors, preventing `x` from being used from outside its scope.^{[[82]][487]}

Lifetimes can be indicated using explicit lifetime parameters on function arguments. For example, the following code
specifies that the reference returned by the function has the same lifetime as `original` (and not necessarily the same
lifetime as `prefix`):^{[[83]][488]}

fn remove_prefix<'a>(mut original: &'a str, prefix: &str) -> &'a str {
    if original.starts_with(prefix) {
        original = original[prefix.len()..];
    }
    original
}

In the compiler, ownership and lifetimes work together to prevent memory safety issues such as dangling
pointers.^{[[84]][489]}^{[[85]][490]}

### User-defined types

[[edit][491]]

User-defined types are created with the `struct` or `enum` keywords. The `struct` keyword is used to denote a [record
type][492] that groups multiple related values.^{[[86]][493]} `enum`s can take on different variants at runtime, with
their capabilities similar to [algebraic data types][494] found in functional programming languages.^{[[87]][495]} Both
records and enum variants can contain [fields][496] with different types.^{[[88]][497]} Alternative names, or aliases,
for the same type can be defined with the `type` keyword.^{[[89]][498]}

The `impl` keyword can define methods for a user-defined type. Data and functions are defined separately.
Implementations fulfill a role similar to that of [classes][499] within other languages.^{[[90]][500]}

#### Standard library

[[edit][501]]
A diagram of the dependencies between the standard library modules of Rust

The Rust [standard library][502] defines and implements many widely used custom data types, including core data
structures such as `Vec`, `Option`, and `HashMap`, as well as [smart pointer][503] types. Rust provides a way to exclude
most of the standard library using the attribute `#![no_std]`, for applications such as embedded devices. Internally,
the standard library is divided into three parts, `core`, `alloc`, and `std`, where `std` and `alloc` are excluded by
`#![no_std]`.^{[[91]][504]}

Rust uses the [option type][505] `Option<T>` to define optional values, which can be matched using `if let` or `match`
to access the inner value:^{[[92]][506]}

fn main() {
    let name1: Option<&str> = None;
    // In this case, nothing will be printed out
    if let Some(name) = name1 {
        println!("{name}");
    }

    let name2: Option<&str> = Some("Matthew");
    // In this case, the word "Matthew" will be printed out
    if let Some(name) = name2 {
        println!("{name}");
    }
}

Similarly, Rust's [result type][507] `Result<T, E>` holds either a successfully computed value (the `Ok` variant) or an
error (the `Err` variant).^{[[93]][508]} Like `Option`, the use of `Result` means that the inner value cannot be used
directly; programmers must use a `match` expression, syntactic sugar such as `?` (the "try" operator), or an explicit
`unwrap` assertion to access it. Both `Option` and `Result` are used throughout the standard library and are a
fundamental part of Rust's explicit approach to handling errors and missing data.

### Pointers

[[edit][509]]

The `&` and `&mut` reference types are guaranteed to not be null and point to valid memory.^{[[94]][510]} The raw
pointer types `*const` and `*mut` opt out of the safety guarantees, thus they may be null or invalid; however, it is
impossible to dereference them unless the code is explicitly declared unsafe through the use of an `unsafe`
block.^{[[95]][511]} Unlike dereferencing, the creation of raw pointers is allowed inside safe Rust code.^{[[96]][512]}

### Polymorphism

[[edit][519]]

Rust supports [polymorphism][520] through [traits][521], [generic functions][522], and [trait
objects][523].^{[[98]][524]}

#### Traits

[[edit][525]]

Common behavior between types is declared using traits and `impl` blocks:^{[[99]][526]}

trait Zero: Sized {
    fn zero() -> Self;
    fn is_zero(&self) -> bool
    where
        Self: PartialEq,
    {
        self == &Zero::zero()
    }
}

impl Zero for u32 {
    fn zero() -> u32 { 0 }
}

impl Zero for f32 {
    fn zero() -> Self { 0.0 }
}

The example above includes a method `is_zero` which provides a default implementation that may be overridden when
implementing the trait.^{[[99]][527]}

#### Generic functions

[[edit][528]]

A function can be made generic by adding type parameters inside angle brackets (`<Num>`), which only allow types that
implement the trait:

// zero is a generic function with one type parameter, Num
fn zero<Num: Zero>() -> Num {
    Num::zero()
}

fn main() {
    let a: u32 = zero();
    let b: f32 = zero();
    assert!(a.is_zero() && b.is_zero());
}

In the examples above, `Num: Zero` as well as `where Self: PartialEq` are trait bounds that constrain the type to only
allow types that implement `Zero` or `PartialEq`.^{[[99]][529]} Within a trait or impl, `Self` refers to the type that
the code is implementing.^{[[100]][530]}

Generics can be used in functions to allow implementing a behavior for different types without repeating the same code
(see [bounded parametric polymorphism][531]). Generic functions can be written in relation to other generics, without
knowing the actual type.^{[[101]][532]}

#### Trait objects

[[edit][533]]

By default, traits use [static dispatch][534]: the compiler [monomorphizes][535] the function for each concrete type
instance, yielding performance equivalent to type-specific code at the cost of longer compile times and larger
binaries.^{[[102]][536]}

When the exact type is not known at compile time, Rust provides [trait objects][537] `&dyn Trait` and `Box<dyn
Trait>`.^{[[103]][538]} Trait object calls use [dynamic dispatch][539] via a lookup table; a trait object is a "fat
pointer" carrying both a data pointer and a method table pointer.^{[[102]][540]} This indirection adds a small runtime
cost, but it keeps a single copy of the code and reduces binary size. Only "object-safe" traits are eligible to be used
as trait objects.^{[[104]][541]}

This approach is similar to [duck typing][542], where all data types that implement a given trait can be treated as
functionally interchangeable.^{[[105]][543]} The following example creates a list of objects where each object
implements the `Display` trait:

use std::fmt::Display;

let v: Vec<Box<dyn Display>> = vec![
    Box::new(3),
    Box::new(5.0),
    Box::new("hi"),
];

for x in v {
    println!("{x}");
}

If an element in the list does not implement the `Display` trait, it will cause a compile-time error.^{[[106]][544]}

### Memory management

[[edit][545]]

Rust does not use [garbage collection][546]. Memory and other resources are instead managed through the "resource
acquisition is initialization" convention,^{[[107]][547]} with optional [reference counting][548]. Rust provides
deterministic management of resources, with very low [overhead][549].^{[[108]][550]} Values are [allocated on the
stack][551] by default, and all [dynamic allocations][552] must be explicit.^{[[109]][553]}

The built-in reference types using the `&` symbol do not involve run-time reference counting. The safety and validity of
the underlying pointers are verified at compile time, preventing [dangling pointers][554] and other forms of [undefined
behavior][555].^{[[110]][556]} Rust's type system separates shared, [immutable][557] references of the form `&T` from
unique, mutable references of the form `&mut T`. A mutable reference can be coerced to an immutable reference, but not
vice versa.^{[[111]][558]}
