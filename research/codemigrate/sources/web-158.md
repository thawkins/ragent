AWS Transform for mainframe’s Reimagine approach differs from its deterministic Refactor COBOL-to-Java pattern: it reverse-engineers COBOL, PL/I, and JCL into structured business rules with acceptance criteria, documentation, data lineage, data dictionary, and domain decompositions, producing S3 artifacts for forward engineering. The post outlines a three-phase workflow with Claude Code: Phase 1 in AWS Transform performs reverse engineering; Phase 2 downloads artifacts outside AWS Transform and uses CLAUDE.md/@imports and Skills to generate specifications, requiring human-in-the-loop review by a software architect or application SME; Phase 3 generates microservice code, tests, database artifacts, and AWS CDK infrastructure, then performs code review, testing, and human verification before production. Claude Code is described as targeting multiple technology stacks/languages/frameworks, tagging each business rule with its source rule ID for traceability, supporting inline builds/tests and Maven-compile hooks, while AWS Transform provides enterprise-scale deterministic reverse engineering; Kiro’s steering files are cited as analogous to CLAUDE.md/@imports and .claude/rules.
