repo-sessions is an MIT-licensed TypeScript tool (zero runtime dependencies, 61 hermetic tests on a 3-OS CI matrix, repo at github.com/firish/repo-sessions) that syncs Claude Code and Codex sessions across machines through one private git repo “vault,” using git hooks (pre-push, post-merge, post-checkout) and tokenizing/rehydrating absolute paths (`${CSS_PROJECT_ROOT}`, `${CSS_HOME}`, `$CODEX_HOME` for Codex) so `claude --resume` works cross-machine. It describes three structural bugs: Windows backslashes inside JSON requiring escaped-path substitution; CRLF/autocrlf and git’s default 1 MiB `http.postBuffer` causing silent multi-megabyte push failures; and self-referential sync metadata/`ai-title` records causing false divergence and a repair that grew a transcript from 471 to 881 to 1701 lines with turns duplicated eight times. The fixes use a compare-only canonical form that folds paths under all known device contexts and strips volatile records, never rewriting stored bytes; design rules are append-only transcripts, never write another tool’s database (Codex SQLite index heals itself after dropping in a rewritten rollout), and degrade invisibly if the vault/tool/repo is unavailable. Usage is `npm i -g repo-sessions`, then `chat setup`/`chat init`, with `chat list`, `chat resume`, `chat rebase`, and `chat restore`; it is dogfooded daily across three machines, including a 400k-token session that resumed cross-OS, and caveats are that the vault must be private (setup refuses public GitHub vaults), pushes run a gitleaks-style secret scan, there is a per-session ignore file, and the vault should be treated like `.env`.
