```text
The documentation-guided legacy migration pattern uses a generated architecture blueprint—covering modules, data flow, APIs, and design rationale—as an intermediate representation: agents document a legacy C repo, plan Rust crates, implement modules while reducing unsafe code, re-document the Rust output and diff it against the original blueprint, then run translated C tests. RustPrint (arXiv:2605.14634) reported 93.26% feature preservation vs. a 52.52% Claude Code baseline and 95.17% test pass rate vs. 79.85% across eight real-world C repositories from 11K–84K LoC, while c2rust produces unsafe Rust and SACTOR reaches 85% semantic preservation but idiomatic refinement still fails 48% on CRust-Bench. The pattern targets large legacy repos without a current architectural owner, generalizes to migrations like COBOL→Java, Perl→Go, and Fortran→modern numerical Rust, and should be skipped for repos under 5K LoC/single-author, inline assembly or hardware-register access, no usable test suite, or heavy macro-driven metaprogramming.
```
