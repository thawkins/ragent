```text
Agent-driven PR slicing has the agent that authored a branch propose smaller, reviewable PRs using chat-session intent and a dependency graph rather than diff clustering; Cursor 3.3 (2026-05-07) ships this as a “Split PRs” quick action, while the open-source DiffEnder/pr-splitter CLI is the diff-only alternative. The pattern targets SmartBear/Cisco findings from ~2,500 reviews across 3.2M lines that defect detection drops sharply above 200–400 lines or 60–90 minutes of review attention, so a 2,000-line branch ideally becomes four 500-line PRs; independent slices land in parallel and dependent slices stack, with GitHub’s native Stacked PRs (gh-stack CLI, public preview 2026-07-30) designed for AI agents. It advises against slicing cross-cutting refactors, atomic-revert/security-sensitive changes, small diffs below ~200 LOC, or work whose chat context was compacted; in the OAuth example, intent-based slicing of a ~1,200-line, 18-file branch yields four dependency-ordered PRs within the 200–400 LOC envelope, whereas file-based slicing fails. It also warns stacking costs rise beyond three to four PRs and that an author approval gate before PR creation is the mitigation.
```
