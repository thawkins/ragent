AWS Transform custom uses a four-phase multi-agent pipeline to generate migration “playbooks” from accumulated artifacts (commit histories, code diffs, error logs, resolution strategies, and decision rationales) to address nondeterminism and improve reproducibility in LLM-based code migration. The book format enables distillation-based quality filtering, practical human correction, structured task guidance, and durable institutional knowledge. In Python Lambda migration experiments, a playbook from 77 repositories had 25% more files and an explicit six-step workflow versus one from 10 repositories; comparing transformation definition alone (TD) with TD + Playbook across Sonnet 4.5, Qwen3 480B, and Devstral-v2 123B judges showed improvements from +4.93% to +15.79%, with five of six comparisons statistically significant (p < 0.05) and up to 15.79% higher consistency. A real example from 78 migrations with 143 dependency-sync attempts embedded retry logic for throttling, where 2–3 attempts typically succeeded, and generated playbooks are integrated into AWS managed transformation packages.
