AWS Transform for mainframe and Kiro are presented as an end-to-end “Reimagine” workflow that reverse-engineers mainframe code into three requirement levels: Level 1 technology-agnostic EARS legacy requirements (REQ-*) with traceability.yaml, Level 2 DDD-based microservice specifications, and Level 3 EARS modernization requirements for code generation. AWS Transform ingests source from S3, builds dependency and data-lineage maps, discovers data paths/business functions, and extracts traceable business rules; Kiro then runs a 5-phase specification pipeline (business-function analysis, bounded-context DDD, microservice spec generation, deterministic traceability verification, and HTML spec generation) via Kiro Power or Skills, with a human-in-the-loop checkpoint before SDD generates requirements.md, design.md, and tasks.md and code with build-verify-fix loops. Validation uses property-based tests (e.g., 100 randomized tries per property) generated from EARS criteria, plus integration/E2E/spec-mutation tests and an auto-repair loop of up to three fix-retest cycles, maintaining traceability back to COBOL business rules.
