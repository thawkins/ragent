In a Coder blog post, Field CTO Nicky Pike argues AI is not a magic button for legacy modernization—it cannot resolve architectural, business, and organizational judgment calls like service boundaries, data consistency, and prioritization—but it is highly useful for grunt work such as code archaeology (mapping dependencies across millions of lines in hours rather than months), pattern recognition, mechanical transformations (a 2–3x productivity boost), and documentation. Serious efforts require private model deployment (e.g., CodeLlama, StarCoder), fine-tuning on the codebase, RAG integration with repos/wikis, secure sandboxed environments like Coder, and a specialized multi-model pipeline for code analysis, transformation, test generation, and security scanning. Pike recommends iterative pair-programming-style prompting, starting with one small well-contained module and measuring time saved, bugs, performance, developer satisfaction, and 2 AM calls before scaling; humans still own architecture and creative decisions. He claims companies adopting this human-AI partnership will modernize faster with fewer bugs, while those waiting for AI to do everything will still be running COBOL in 2035.
