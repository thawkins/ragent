```text
The article describes building an end-to-end agentic AI workflow to modernize mainframe applications to cloud-native architecture using AWS Transform and Kiro, with other agentic frameworks such as Amazon Q CLI also possible. It claims mainframe migration can reduce operational costs, address skill shortages, improve agility, and speed innovation, but is complex, costly, and failure-prone; the first successful migration was in the early 1990s, while older Replatform/Refactor patterns are tool-based yet often insufficient because manual rewrites extend timelines and raise failure rates due to labor-intensive business-logic extraction. Generative AI enables a ReImagine pattern in which agents extract business logic from COBOL and other mainframe languages and generate code, test cases, test data, compile, fix bugs, test, and deploy; AWS Transform documents business rules in Gherkin/BDD, generates UI/data-source details, and produces HTML/JSON outputs—application documentation, program flows, business rules, UI, and data-source details—that become EPICs/user stories and target specs (data models, architecture, API contracts) via iterated workflows using SRS or DDD, steering documents, and MCP integrations to JIRA, Confluence, Git, and AWS. The workflow has three swim-lanes (human user, external tools/services, agent frameworks): a developer uploads mainframe code as a zip to Amazon S3, submits an AWS Transform job, and in sprints agents generate incremental code, tests, test data, IaC/scripts, cross-check Definition-of-Done, push stories to In Review, then after human review commit to Git and deploy to Dev/Test, with Human-In-The-Loop emphasized. The conclusion says mainframes still process billions of transactions daily, but cost, limited agility, and skill shortages drive migration, citing Netflix, Epic Games, and Amazon as AWS-scale examples and quoting “Mainframe helped humans reach Moon, Cloud will take us to Mars!!” while expecting agentic AI to further reduce barriers.
```
