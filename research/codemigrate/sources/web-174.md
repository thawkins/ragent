claude-code-migration v0.2.0 is its first beta release, validated against 50 real local Claude Code projects × 4 target agents = 92 migrations without failure, with 88 tests covering every source parser, target adapter, security guard, and hub integration path. It introduces the vendor-neutral Workspace Dossier (项目档案; internally formerly CanonicalData), which packs memories, agents, skills, sessions, and MCP configs into one portable JSON file; the CLI supports `ccm export`/`ccm apply`/`ccm migrate`, and any-to-any migration via reverse source parsers yields 5 sources × 4 targets = 20 combinations (e.g., Cursor → OpenCode, Hermes → Windsurf). Security hardening includes redaction of MCP Bearer tokens, pasted API keys, and `*_API_KEY=...` shell snapshots to `${CC_<PATH>}` placeholders; `dossier.json`/`scan.json` now use 0o600 (prior 0o644); `parse_cowork_zip` rejects entries >500 MB or compression ratio >1000×; `--in-place` rejects dirty git trees unless `--force`; `--token-stdin` protects the neuDrive token from `ps aux` (bare `--token` still works with a stderr warning); and Hub rejects `..` path traversal. The scanner now captures 60+ data types—including session JSONL bodies, subagent transcripts, tool-result sidecars, full `plans/*.md` and `todos/*.json`, parsed `history.jsonl` entries, `~/.claude.json` per-project state, shell snapshots, session-env bundles, file-history, and `mcp-needs-auth-cache`—and installation is via `pip install claude-code-migration` or `pipx`; breaking changes from 0.1.0 include `--ir` as an alias for `--dossier`, default output `ir.json` → `dossier.json`, and renamed internal helpers such as `_write_ir` → `_write_dossier`.
