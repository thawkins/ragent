The article argues that for repo-wide changes, the choice between Claude Code and scripts should depend on whether the transformation requires interpretation or consistency, not file count: a deterministic change across 4,000 files can fit a script better than a context-dependent change across 40. It recommends scripts/codemods/AST transforms first for mechanical work—renames, import-path rewrites, config-key migrations, exact helper replacements—because they are deterministic, auditable, rerunnable, cheaper to scale, and less likely to drift; Claude Code is better for the semantic tail, such as deprecated API replacements with multiple context-dependent destinations (e.g., `fetchUser()` becoming `findVisible`, `findIncludingArchived`, `findForProcessing`, or a fake repository). A staged workflow is advised: isolate the deterministic core, run tests/static analysis, classify failures, use Claude Code only on the exception set (e.g., 27 failed files), and rerun the script as needed. Practical rule: if the migration rule can be stated more clearly as code than prose, start with a script; if it needs examples, caveats, and “except in these cases,” Claude Code becomes attractive—use scripts for bulk certainty and Claude Code for semantic exceptions.
