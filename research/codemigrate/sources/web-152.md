```text
Microsoft's Foundry Agent Service migration guide says a GitHub migration tool can automate migrating agent definitions and thread/message/run creation code from the Assistants API/classic agents to the new Agents API, but it does not migrate state data such as past runs, threads, or messages. The new API uses conversations instead of threads and responses instead of runs; agent creation/versioning uses the project/Agents client, while conversations and responses use the OpenAI client. Prerequisites include an Azure subscription, a Microsoft Foundry project, and SDKs such as Python `azure-ai-projects>=2.3.0`, .NET `Azure.AI.Projects`/`Agents`/`Extensions.OpenAI` with `Azure.Identity`, Node.js 22+ with `@azure/ai-projects` 2.4.0, and Java `azure-ai-agents` 2.2.0 plus `azure-identity` 1.18.4. Claimed benefits include more Foundry models; tools such as Web Search, File Search, Code Interpreter, MCP, image generation, and reasoning summaries; Responses API foundation; background mode; prompt-based and Hosted agents; single-tenant storage with optional Azure Cosmos DB; enhanced security; separation of duties; and deployable agents. Tool availability changes include A2A added (GA; `a2a_preview` remains Public Preview), Azure Functions and Connected Agents removed (Connected Agents recommends A2A), Deep Research removed (recommends Deep Research model with Web Search tool), and Image Generation and Web Search added.
```
