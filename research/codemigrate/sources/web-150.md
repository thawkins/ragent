Microsoft's Foundry Agent Service migration guide covers moving from the Assistants API/classic agents to the new Agents API, offering a GitHub migration tool that automates code constructs such as agent definitions, thread/message/run creation but does not migrate state data like past runs, threads, or messages. It requires an Azure subscription, a Microsoft Foundry project, and SDK/identity packages including Python `azure-ai-projects>=2.3.0`, Node.js 22+ with `@azure/ai-projects` 2.4.0, and Java `azure-ai-agents` 2.2.0 plus `azure-identity` 1.18.4; the core API mapping is threads→conversations, runs→responses, and assistants/classic agents→new agent versions via `client.agents.create_version()`. New capabilities include any Foundry model, Web Search, File Search, Code Interpreter, MCP (preview to GA), image generation (preview), reasoning summaries, background mode/durable streams, prompt-based and Hosted agents, single-tenant storage with optional Azure Cosmos DB, enhanced security, separation of duties, and deployable agents, while tool availability changes include removal of Azure Functions, Connected Agents, and Deep Research (recommending A2A and Deep Research model with Web Search) and addition of A2A and Web Search. The guide lists four minimum migration steps: compare tools and choose replacements, migrate the agent definition, replace threads/runs with conversations/responses, and verify state, tool calls, outputs, and error handling.
