```text
Andrew Mercer’s Aug. 7, 2026 guide argues large migrations are a thousand nearly identical tasks, so a pipeline—pilot 5–10 varied files, review the agent’s output as a spec, write a rules file (e.g. `MIGRATION.md` with “stop and list it”), batch 10–40 dependency-aligned files with one commit and green build each—beats one long agent session. For the mechanical ~80%, codemods beat agents; on a 109-file/23,330-line/902,586-byte corpus with 65 `interface` declarations, a `sed` one-liner changed 65 declarations across 46 files but left 8 `tsc --noEmit` errors (214 if the one `.d.ts` was included), whereas a 116-line TypeScript-compiler-API codemod rewrote 63, refused 2, changed 45 files, and stayed clean in 189 ms. The agent is worth it on the residual ~20% needing inferred intent (e.g., placeholder types, `componentDidUpdate`→`useEffect` deps, behavioural assertions); estimated costs are ~258K tokens (~$1.29 at Opus 5’s $5/M input) for that corpus and ~2.8M tokens (~$14) for 1,200 files. Cited reports: Slack’s 15,000+ Enzyme tests→React Testing Library reached 45% codemod-only, 40–60% LLM-only, and 80% combined; Google’s JUnit3→JUnit4/int32→int64 migration had 80% fully AI-authored landed changes with AST tooling, moving 5,359 files and 149,000+ lines in three months amid review-capacity bottlenecks; Airbnb’s pre-LLM `ts-migrate` converted 50,000+ lines/1,000+ files in a day by inserting `any` and suppression comments. Parallelism works via git worktrees (3–5 agents before attention limits), and when no test signal exists, characterization tests should record current behaviour.
```
