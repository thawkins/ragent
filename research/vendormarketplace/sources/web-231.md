According to agent-connector.ai’s host-hooks guide, hooks are host lifecycle callbacks rather than model-selected MCP tool calls, and each CLI exposes them differently; agent-connector normalizes them into `json-stdio` (e.g., Claude Code `PreToolUse` via Settings JSON, Codex CLI `hooks.json`, Gemini CLI events like `BeforeTool`, `AfterTool`, `PreCompress`, `BeforeAgent`), `ts-plugin` (e.g., OpenCode’s `tool.execute.before` and `permission.ask`), and `mcp-only` hosts (e.g., Warp, Cline, Zed) where declared hooks are skipped with a warning. It cross-validates hook-capable hosts from adapter metadata and docs drift tests, dispatches via the stable `agent-connector hook <host> <event> --connector <id>` command, and translates native host payloads into normalized events and responses. The guide stresses hooks are additive policy, not a substitute for server-side validation, should stay fast and return small context, and cross-host behavior should be tested with one host per paradigm.
