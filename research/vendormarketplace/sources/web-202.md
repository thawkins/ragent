The page explains how to build and host Claude Code plugin marketplaces—catalogs for distributing plugins across teams and communities with centralized discovery, version tracking, automatic updates, and support for git repositories, local paths, and other source types. It covers creating `.claude-plugin/marketplace.json` (required `name`, `owner`, and `plugins`; each plugin needs `name` and `source`), plugin sources such as relative paths, GitHub repositories, and git URLs, optional metadata and component configs (commands, agents, hooks, MCP/LSP servers), `strict` mode for `plugin.json`, hosting on GitHub/GitLab/Bitbucket/self-hosted git, user commands like `/plugin marketplace add`, `/plugin install`, and `/plugin marketplace update`, team settings via `extraKnownMarketplaces` and `enabledPlugins` in `.claude/settings.json`, and managed restrictions via `strictKnownMarketplaces` (undefined = no restrictions, `[]` = complete lockdown, list = exact-match allowlist validated before network/filesystem operations). It also notes validation with `claude plugin validate .` or `/plugin validate .`, and troubleshooting: URL-based marketplaces download only `marketplace.json` so relative paths fail, while installed plugins are copied to a cache so references outside the plugin directory fail.
