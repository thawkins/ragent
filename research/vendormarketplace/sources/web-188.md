PR openai/codex#18182 concerns remote sync state for dropped marketplace entries: `sync_remote_plugins` iterates `curated_marketplace.plugins`, but `load_marketplace` now removes manifest-broken entries upstream, so those plugins never reach sync reconciliation—meaning remote disable/uninstall state can be ignored and stale local enable/install config can persist. Codex review flagged several issues: `find_installable_marketplace_plugin` enforces availability only after `find_marketplace_plugin` resolves a source, so entries returning `Ok(None)` for invalid/unsupported sources are skipped, allowing a restricted first duplicate to be bypassed by a later installable duplicate of the same name (potentially permitting install instead of `PluginNotAvailable`); matching-but-skipped entries fall through to `PluginNotFound`, misclassifying policy-restricted plugins for clients; removal of the `codex_plugin::PLUGIN_MANIFEST_PATH` re-export is a breaking API change unrelated to alternate manifest discovery; and `load_marketplace` silently skipping `InvalidPlugin` entries can leave an empty marketplace with no `marketplaceLoadErrors`, hiding configuration bugs.
