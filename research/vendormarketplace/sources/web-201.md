The author runs Claude Code sessions in short-lived k3s pods and wanted plugin installs from a self-controlled local server instead of github.com. The solution requires a smart-HTTP git server—nginx + fcgiwrap + git-http-backend, with Alpine’s git-daemon package providing `/usr/libexec/git-core/git-http-backend`—because Claude Code shallow-clones marketplaces and dumb static HTTP fails with “dumb http transport does not support shallow capabilities.” The server exports a bare, clone-only repo at `/srv/git/jbmurphy-plugins.git`, whose `.claude-plugin/marketplace.json` uses relative-path plugin sources (`executor`, `eventforge`); one Node/Bun MCP plugin is bundled via `bun build` from 68 MB of node_modules into a 900 KB `dist/index.js`, with `package.json` kept out of the served directory. Clients run `claude plugin marketplace add https://marketplace.local.jbmurphy.com/jbmurphy-plugins.git` and `claude plugin install eventforge@jbmurphy-plugins`; the k3s nginx deployment sits behind a reverse proxy where the WAF “block common exploits” option must be disabled for git smart-HTTP, and updates come from rebuilding the marketplace image.
