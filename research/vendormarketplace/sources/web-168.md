`Codex.Plugins` owns local plugin authoring for Codex-native `.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`, and minimal local plugin trees, while read/path helpers also accept Claude-compatible `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`; it is separate from `Codex.AppServer.plugin_*` and uses normal Elixir file IO without a running Codex subprocess. APIs include `new_manifest/1`, `write_manifest/3`, and `scaffold/1`, which returns plugin root, manifest path, optional marketplace path, and skill paths; validation enforces a non-empty kebab-case manifest name, `./`-relative component/interface paths that cannot escape with `..`, at most 3 `interface.defaultPrompt` entries of ≤128 normalized characters, deterministic JSON with trailing newline, no `mix.exs`/`.formatter.exs`/`build_support/*`/Dialyzer/PLT generation in phase 1, and preservation of unknown forward-compatible keys in extra maps. Scope defaults to `<repo-root>/plugins/<plugin-name>` and `<repo-root>/.agents/plugins/marketplace.json` for repo, or `~/plugins/<plugin-name>` and `~/.agents/plugins/marketplace.json` for personal, with `root:` or `marketplace_path:` overrides; write/scaffold default to Codex-native paths, while reads/validation accept either location when explicitly passed or when only the alternate manifest exists. Authoring stays local and is not routed through app-server `fs/*`, runtime verification stays on app-server, literal CLI marketplace uses `Codex.CLI.marketplace_add/2`, and upstream treats hooks from newly installed/updated materialized workspace plugins as trusted only after effective-plugin refresh succeeds and current hook hashes are written for the active account (fail-closed on account change or config-write failure), without changing the SDK’s local authoring or manifest-validation APIs.
