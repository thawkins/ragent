OpenAI's Codex uses a manifest-first plugin system in which each plugin is defined by a sole required file, `.codex-plugin/plugin.json`, and only the kebab-case `name` field is strictly required. The manifest can reference up to four bundled component types — Skills (the "brain"), Apps/connectors (auth), MCP Servers (tools), and lifecycle Hooks — via `./`-prefixed paths; SDK-enforced validation (Elixir `Codex.Plugins.Manifest.parse!/1`) rejects `..` escapes and caps `defaultPrompt` at 3 entries of ≤128 characters, while unknown keys are preserved through extra maps for forward compatibility. Distribution is Git-native via marketplace JSON catalogs at official, repository (`$REPO_ROOT/.agents/plugins/marketplace.json`), personal (`~/.agents/plugins/marketplace.json`), and legacy Claude-compatible scopes, with plugins installing to `~/.codex/plugins/cache/$MARKETPLACE/$PLUGIN/$VERSION/` and state tracked in `enabledPlugins` settings files. Plugin hooks are non-managed and do not auto-execute until a user explicitly reviews and trusts them, and MCP servers are described as the portable interop layer across Codex, Claude Code, and Cursor. The report is dated June 26, 2026, cites OpenAI Codex docs and Codex SDK v0.16.1 (HexDocs), and rates confidence High.
