Verdent’s Codex CLI MCP setup guide explains that MCP lets Codex act as a client to external MCP servers so it can fetch tools and live context—such as GitHub, Notion, Linear, Sentry, Vercel, internal tools, or CI/CD data—instead of requiring manual pasting. It supports stdio and Streamable HTTP transports, configured in `~/.codex/config.toml` or a trusted project’s `.codex/config.toml`, with CLI commands like `codex mcp add/list/show/remove/login` and `/mcp` for in-session verification; config precedence is project `.codex/config.toml` closest to cwd, then project root, then global. Key defaults/troubleshooting include a 10-second startup timeout and 60-second tool timeout (overridable via `startup_timeout_sec` and `tool_timeout_sec`), `bearer_token_env_var` expecting the env-var name rather than the token, possible need for absolute stdio executable paths, OAuth limitations in headless environments, and project config loading only for trusted projects.
