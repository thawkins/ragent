OpenClaw’s native plugin manifest is `openclaw.plugin.json`, required in every plugin root and read before plugin code executes to validate config and expose pre-runtime metadata such as `id`, `configSchema`, auth/setup, activation hints, CLI/MCP/dashboard/backup/QA surfaces; missing or invalid manifests block config validation and are treated as plugin errors. Compatible bundles instead use `plugin.json` (Agent Plugins), `.codex-plugin/plugin.json` (Codex), `.claude-plugin/plugin.json` or the default Claude layout, or `.cursor-plugin/plugin.json` (Cursor), which OpenClaw auto-detects but does not validate against its schema. `id` and `configSchema` are required top-level fields; manifests are parsed with JSON5 and only documented fields are read, with config validated against the JSON Schema at read/write and before load. Validation treats unknown `channels.*` keys as errors unless plugin-declared, unknown plugin ids in `plugins.entries`/`plugins.allow`/`plugins.deny` as warnings, and broken/missing schemas as failures reported by Doctor; exclusive plugin kinds use `plugins.slots.*` (`memory`/`contextEngine`), and runtime `OpenClawPluginDefinition.kind` was deprecated on 2026-07-25 with a removal gate of 2026-10-01.
