GitLab Runner administration covers installing and registering runners, configuring executors, and scaling job execution infrastructure. Installation supports Linux, Windows, macOS, and z/OS; registration uses authentication tokens and access scopes for instance, group, or project runners, with tags in `.gitlab-ci.yml` routing jobs. Administrators choose executors such as shell or Docker, configure runners via the auto-generated `config.toml` (including concurrency, logging, cache, CPU, and executor-specific settings), and can run jobs on the local machine, containers, Kubernetes, or autoscaled cloud instances. Advanced features include autoscaling, fleet management, and Prometheus metrics for active jobs, CPU, memory, success rates, and queue lengths.
