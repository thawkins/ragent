agent-connector’s host hooks guide states hooks are host lifecycle callbacks, not model-selected MCP tool calls, and normalizes differing CLI hook transports into three paradigms: `json-stdio` (e.g., Claude Code, Codex CLI, Gemini CLI, Cursor, GitHub Copilot CLI, Qwen CLI, Goose, OpenHands), `ts-plugin` (OpenCode, Kilo CLI, OpenClaw), and `mcp-only` hosts (Warp, Cline, Zed, Windsurf, Junie) where declared hooks are skipped with a warning. Dispatch converts a native host payload into a normalized event, runs the connector handler, then translates responses such as context, allow/block, or warning text back to the native contract; unsupported events or responses surface as warnings. The guide stresses hooks are additive policy, not a replacement for server-side validation, and recommends matchers, per-host overrides, `platforms.<id>.nativeHooks`, disabling hooks per host, fast handlers, small context output, and testing one host per paradigm before claiming cross-host behavior.
