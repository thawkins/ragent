NeonCodex’s Connectors documentation says the AI can search and act in connected apps—Gmail, Microsoft 365, GitHub, Shopify, Zoho, Notion, Slack, databases and more—by calling them live rather than using a synced copy. Connectors are available on Pro, Teams, and Enterprise with Claude and other tool-capable models (GPT-5.x, Gemini, DeepSeek, Qwen, GLM, Kimi, Grok, MiniMax); Free and other models instead get the connector’s last synced summary. Apps can be chosen per message or set to “Use in every task,” tasks show call/change counts such as “GitHub: 3 calls, 1 change,” reads are treated as data not instructions, change tools only appear for selected apps and when requested, and tokens are encrypted, per-call, and not stored with the task. The docs list read/change tools across many services—including GitHub, GitLab, Google Workspace, Microsoft 365/Outlook/OneDrive/SharePoint/Teams, Slack, Notion, Linear, Jira, Confluence, HubSpot, Salesforce, Zoho, Asana, Figma, Trello, Stripe, PayPal, Square, Shopify, QuickBooks, Xero, Cloudflare, Lovable, Airtable, PostgreSQL, MongoDB, Supabase, Firebase, Snowflake, Mixpanel, and IMAP email—with approval required for changes unless “Always allow” is set under Settings > Permissions. Specific constraints include PostgreSQL/MongoDB/Snowflake being read-only, one query at a time, with row/time limits and internet reachability; Supabase using REST/RLS; Firebase using a Cloud Firestore service-account JSON; Gmail/Outlook/IMAP never deleting mail and sending only when asked; Microsoft Teams/SharePoint requiring a work or school Microsoft 365 account; Teams channel reads needing admin approval; and Trello connecting via API key/token. Keys, app passwords, and connection strings are tested, encrypted, and never shown again.
