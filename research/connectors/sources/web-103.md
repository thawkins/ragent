Structured outputs constrain Claude to schema-valid, parseable responses through two combinable features: JSON outputs (`output_config.format`, schema type `json_schema`) and strict tool use (`strict: true`), using constrained decoding to prevent malformed JSON, missing fields, type/schema violations, and retries. Schemas follow JSON Schema with limits: basic types, enum/const, anyOf/allOf, `$ref`/`$def`/definitions, default, required, `additionalProperties:false`, selected string formats, and array `minItems` 0/1 are supported; recursive schemas, complex enum types, external `$ref`, numerical/string constraints, other `additionalProperties` values, and complex regex features like backreferences, lookahead/lookbehind, and word boundaries are not. Compiled grammars add first-request latency, cache for 24 hours from last use, invalidate on schema or tool-set changes (not name/description-only changes), can return 400 “Schema is too complex” or hit a 180-second compilation timeout, and an injected system prompt raises input tokens; changing `output_config.format` invalidates prompt cache, required properties appear before optional ones, and outputs can still not match the schema on refusals (`stop_reason: refusal`, 200, billed), `max_tokens`, or enum capitalization differences. Migration uses `output_config.format` (deprecated `output_format` requires beta header `structured-outputs-2025-11-13`; Python SDK v1.0 rejects `output_format`); data uses ZDR with schemas cached up to 24 hours and HIPAA eligibility only if PHI is excluded from schemas. It works with batch processing at 50% discount, token counting, streaming, and combined JSON+strict use, but not citations or message prefilling, and is supported on Claude API, AWS, Amazon Bedrock (Opus 4.6, Sonnet 4.6/4.5, Opus 4.5, Haiku 4.5), Google Cloud, and Microsoft Foundry across models including Fable 5/5.1, Mythos 5/5.1/Preview, Opus 4.5–4.8/5/5.5, Sonnet 4.5/4.6/5/5.5, and Haiku 4.5.
