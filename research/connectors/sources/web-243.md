MCP (Model Context Protocol) configuration uses JSON files—typically `.mcp.json`—with a top-level `mcpServers` object whose entries define `command`, `args`, `env`, and allowed tools; MCP comprises an MCP client (e.g., Claude or VS Code), an MCP server hosting tools, and an MCP host environment (local or cloud). Config scope determines precedence: user `~/.mcp.json`, project `./mcp.json`, and local `.vscode/mcp.json`, with the most specific scope overriding; discovery checks local IDE files, then project, then user files, and VS Code can discover servers configured in Claude Desktop. Credentials should not be hardcoded—use `${input:...}` prompts or `${env:...}` references, gitignore `.mcp.json`/`.env`, and provide `mcp.example.json` templates. Operationally, MCP supports STDIO for local servers and SSE for remote servers with URL/headers; common failures include command-not-found, invalid JSON, missing tool registration/schema errors, and timeouts adjustable via `MCP_TIMEOUT=10000` (10 seconds), while clients offer `claude mcp add/list` and VS Code commands, and Stainless auto-generates MCP servers from OpenAPI specs.
