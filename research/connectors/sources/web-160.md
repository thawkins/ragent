Anthropic's beta Claude API MCP connector (`anthropic-beta: mcp-client-2025-11-20`) lets a Messages API request use remote MCP server tools, with Anthropic's infrastructure acting as MCP client and no client-side tool-execution loop; requests must pair an `mcp_servers` entry (`type:"url"`, HTTPS `url`, `name`, optional `authorization_token`) with exactly one `mcp_toolset` in `tools` (`type:"mcp_toolset"`, `mcp_server_name`), or validation fails. Toolset configuration supports `default_config` and per-tool `configs` with `enabled` (default true), `defer_loading` (default false; pairs with tool search for large toolsets), and `cache_control`, with precedence tool-specific > default_config > system defaults; allowlist/denylist patterns work, but unknown tool names only log a backend warning. Responses return `mcp_tool_use` (id prefix `mcptoolu_`, name, server_name, input) and `mcp_tool_result` (tool_use_id, is_error, content) blocks; limitations are tools only (not prompts/resources), public HTTPS Streamable HTTP/SSE only (no local stdio/private-network URLs), caller-managed OAuth with no Anthropic token refresh, beta availability on Claude API, Claude Platform on AWS, and Microsoft Foundry (Hosted-on-Anthropic) but not Amazon Bedrock or Google Cloud Vertex AI, not ZDR-eligible, and Message Batches API support at regular pricing. The deprecated `mcp-client-2025-04-04` used optional `tool_configuration`/`allowed_tools` inside `mcp_servers`, while the current version mandates exactly one toolset per server; common pitfalls include missing/mismatched toolset or server name, localhost/internal URLs, expecting token refresh, and silent typos in `configs`, and the docs still link the MCP spec's 2025-11-25 authorization section rather than 2026-07-28.
