Codex MCP servers are configured in `~/.codex/config.toml` (or project-scoped `.codex/config.toml`) as `[mcp_servers.<name>]` snake_case tables, with `CODEX_HOME` relocating the user directory and remote servers using streamable HTTP via `url` plus `bearer_token_env_var`, `http_headers`, or `codex mcp login` for OAuth; common failures include silently ignored section-name typos, “not supported for stdio” from mixed transports, slow `npx` cold starts fixed by `startup_timeout_sec`, tool calls bounded by `tool_timeout_sec`, env vars needing explicit passing, and TOML inline-table/string syntax errors. For Stripe, the page contrasts direct `npx -y @stripe/mcp-server` with `STRIPE_SECRET_KEY` against registering Stripe in PolicyLayer, minting a grant, and pointing Codex at `https://proxy.policylayer.com/mcp/<server-uuid>/` with `Authorization: Bearer <grant-token>` (or `codex mcp add stripe --url ... --bearer-token-env-var POLICYLAYER_GRANT`), so the live key leaves the config. PolicyLayer’s gateway adds per-grant/team rate limits per minute/hour/day, argument-based allow/deny/conditional gating (example: default deny, allow `list_customers`, allow `create_charge` but deny `args.amount > 50000` cents), amount-based counters/budgets, audit records of grant/tool/argument keys/deciding rule, and compliance mapping for SOC 2, HIPAA, and GDPR.
