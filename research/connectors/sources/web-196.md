Gety’s connector contract defines `manifest.json` (changes require reinstalling; `entry`/`icon` must stay in the connector root; unknown fields rejected), a polling `schedule`, ordered `config.fields` rendered in the install/config UI and exposed as typed `this.config` (`type: "password"` for secrets; local validation uses `GETY_CONFIG_`-prefixed env vars), `doc_link` for document-open behavior (`url` opens in browser, `file` requires stable local paths; `content_format` only controls text preview), and `schema.extra_gety_indexed_fields` for searchable metadata. Connectors are default-exported classes extending `Connector<Config, State>`; each scheduled poll starts a fresh runtime, so durable data must use `state` or an on-disk cache. Documents use `upsert(doc)`/`del(id)`, only `id` and `title` are required, content is limited to about 10 MB, and `poll()` yields `PollResult` batches with updates plus optional state checkpoints—checkpoint after updates, don’t advance state early, emit deletes only from real signals, and page/stream source data. Validation runs `verify` (`fix`, `check`, `test`, `build`); the local runner persists state at `dev/.runner/state.json` and writes snapshots under `dev/runs/<timestamp>/` (`.md` for markdown, `.txt` otherwise, plus `.json` sidecar); after editing `src/index.ts`, run `deno task build` and click Restart in Gety.
