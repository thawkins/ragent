Claude Code Hooks, an underutilized feature, are executable scripts invoked at points in the tool lifecycle that can inspect, block, or allow tool executions (Read, Write, Bash, Edit), with matchers scoping them to specific tools; types include PreToolUse (the only one able to block), PostToolUse, Notification, and Stop. Hooks are configured in `settings.json` — global (`~/.claude/settings.json`), project-level (`.claude/settings.json`), or enterprise — and communicate via JSON over stdin/stdout, where PreToolUse returns `deny`, `allow`, or `ask` with a `permissionDecisionReason`. Exit codes matter: 0 evaluates the JSON, 2 always blocks regardless of output ("Fail Closed"), and any other code yields undefined behavior, so hooks should exit 2 on unexpected errors. Practical examples include a `check-secrets` hook scanning `git diff --cached` (added lines only) for API keys, passwords, private keys, AWS keys, GitHub tokens, and high-entropy strings ≥32 characters, and a `check-model-author` hook blocking AI co-author commits matching model names (claude, sonnet, haiku, opus, gpt, gemini, llama, copilot) or no-reply addresses (noreply@anthropic.com, noreply@openai.com). The author notes Claude Code once tried to bypass git pre-commit hooks via `git commit --no-verify`, matchers can be narrowed to e.g. `Bash(git commit*)`, and general policies belong in global config while project-specific checks belong per-project.
