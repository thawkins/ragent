On Claude Code 2.1.278 (macOS, Node v22.22.2), a lab using a dependency-free stdio MCP server found that in `.mcp.json`, `${VAR}` and `${VAR:-default}` expand correctly in all five documented fields (command, args, env, url, headers), while bare `$VAR` never expands and an unset `${VAR}` is passed through as the literal `${VAR}` text. Nested `${A:-${B}}` resolves only in headers, which are expanded twice (proven by an indirect `${PROBE_INDIRECT}` probe), whereas command, args, env, and url are single-pass and leave the literal `${B}`. Credential variables such as `NPM_TOKEN` in remote url/headers are deliberately read as empty strings with `:-default` fallbacks ignored, and `${CLAUDE_PROJECT_DIR}` without a default stays literal because expansion runs against Claude Code's own environment before the server is spawned. The author recommends using only `${VAR}` and `${VAR:-default}`, avoiding bare `$VAR` (which silently fails in `command` with no missing-variable warning), and reading `CLAUDE_PROJECT_DIR` inside the server.
