OGX provides `ogx connect claude`, a single command that discovers models via the OGX server’s `/v1/models`, filters non-LLM models, maps LLM models to Claude Code’s haiku/sonnet/opus tiers, sets `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` and tier env vars, unsets Vertex/Bedrock variables, and launches Claude Code; by default all tiers use the first available LLM, with `--model`, per-tier flags, `--host` (localhost), `--port` (8321 or `OGX_PORT`), and `--print-env` available. OGX implements the Anthropic Messages API at `/v1/messages`, translating messages, tool calls, streaming, and thinking blocks to/from OpenAI formats when needed, with native passthrough for Anthropic, Ollama, and vLLM; supported features include multi-turn/system messages, streaming, tool use, extended thinking, token counting (`/v1/messages/count_tokens`), prompt caching only where providers support it, and any inference provider (OpenAI, vLLM, Ollama, Fireworks, Together, Groq, Bedrock). Caveats include OpenAI `max_tokens` errors (e.g., Claude Code requesting 32000 when a model supports at most 16384), Claude Code bypassing `ANTHROPIC_BASE_URL` if Vertex/Bedrock vars are set, and ~5–20 ms translation overhead plus double-proxy latency for cloud providers, while model-dependent limits differ (Anthropic 200K+ tokens vs. Qwen3 32K, Llama3 128K). Manual setup uses `ANTHROPIC_BASE_URL=http://localhost:8321`, `ANTHROPIC_AUTH_TOKEN=ogx`, and `ANTHROPIC_DEFAULT_HAIKU_MODEL`/`SONNET`/`OPUS`; starter aliases `claude-haiku-4-5-20251001` across providers, and the Claude Agent SDK can use OGX as a drop-in backend.
