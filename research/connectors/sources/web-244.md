ConnectorZone’s guide describes four MCP server configuration patterns: environment variables, CLI arguments, config files, and per-request HTTP headers. Environment variables are the most portable, work for stdio and remote servers, suit credentials, hostnames, ports, and feature flags, and are read via `process.env`/`os.environ`, but should not hold structured data or committed secrets; CLI arguments in the `args` array suit non-sensitive structural options like paths, `--read-only`, and numeric limits but are exposed in process listings. Config files handle complex structured configuration—such as multiple database backends or `queriesPerMinute: 60` rate limits—with the path passed via env var or CLI, while credentials should come from a secrets manager and files should be `chmod 600`. Remote Streamable HTTP servers can use per-request headers like `Authorization: Bearer ...` for per-user/session access and OAuth over HTTPS, whereas static server-wide credentials belong in server-side config. Environment variables give the most consistent cross-client behavior, though Claude Desktop and VS Code dialects differ in root keys and environment-block handling.
