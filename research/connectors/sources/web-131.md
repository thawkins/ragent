Per-server MCP environment scoping spawns each MCP server with an explicit minimal env block—e.g., GitHub sees `GITHUB_TOKEN`, Postgres sees `DATABASE_URL`, Stripe sees `STRIPE_KEY`—so a compromised server’s blast radius is bounded; without it, the host passes `os.environ` via `execve(2)`. The MCP spec does not mandate scoping, but the reference Python SDK’s `stdio_client` merges `StdioServerParameters.env` with a hard-coded allowlist (`HOME`, `PATH`, `SHELL`, `USER`, platform vars), and Claude Code (`.mcp.json`, `claude mcp add --env`), VS Code Copilot (`.vscode/mcp.json`, `envFile`, `${input:id}`), and Codex CLI (`config.toml` `mcp_servers.<name>.env`) expose per-server env knobs. For streamable HTTP MCP servers, OAuth tokens belong in a per-server credential store/keychain rather than env (Claude Code `oauth.scopes`; Codex CLI 0.134.0), since kernel-enforced process boundaries make default-deny stronger than runtime allowlisting. The pattern converts missing credentials into loud startup auth failures and is the configuration-layer complement to proxy-based credential isolation and workload identity federation, though it does not protect the agent’s own environment and may be redundant in already isolated or broad-ambient-access environments.
