MetaMCP reads a `.mcp.json` file whose single top-level key is `mcpServers`, a `Record<string, ServerEntry>` mapping server names to configs, matching the Claude Desktop/Claude Code format. Each server entry requires `command` and optionally supports `args` (default `[]`) and `env` (default `{}`), with env vars scoped only to that server’s child process; all servers default to “vital” criticality with one automatic retry-on-crash. Defaults include config path `.mcp.json` in the current directory, pool max connections 20, reserve size 0, minimum size 0, reserve timeout 5,000 ms, idle timeout 300,000 ms, circuit breaker threshold 5 consecutive failures, and cooldown 30,000 ms. Config lookup checks `--config` then `.mcp.json` in the cwd; if none exists, MetaMCP starts with zero child servers and `mcp_provision` can add servers at runtime. Server names are used in `mcp_call`, as `servers.<name>` in `mcp_execute`, and in `mcp_discover` results/status.
