Anthropic’s structured outputs use constrained decoding to make Claude return JSON Schema-valid responses via `output_config.format` (JSON outputs) and/or `strict: true` (strict tool use), eliminating invalid JSON, missing fields, type errors, and schema-violation retries. They support basic JSON Schema types, enums/consts, anyOf/allOf, `$ref`/`$def`/definitions, selected string formats, required fields with `additionalProperties: false`, and `minItems` 0/1, but not recursive schemas, external `$ref`, numerical/string constraints, `additionalProperties` other than false, or complex regex; SDK helpers strip unsupported constraints into descriptions and validate against the original schema, while compiled grammars cache for 24 hours from last use (first-request latency; schema/tool/`output_config.format` changes invalidate cache; an injected system prompt adds token cost). It is ZDR/HIPAA eligible but schemas cache up to 24h and must not contain PHI; outputs may still mismatch on refusal (`stop_reason: "refusal"`, HTTP 200, billed), `max_tokens`, enum capitalization, or complexity limits (400 “Schema is too complex” / 180s timeout), and it works with Batch (50% discount), token counting, streaming, and combined JSON+strict tools but not citations or message prefilling; `output_format` is deprecated for `output_config.format` (old beta header `structured-outputs-2025-11-13`), supported on Claude API, Claude Platform on AWS, Amazon Bedrock, Google Cloud, and Microsoft Foundry for listed Fable, Mythos, Opus/Sonnet 4.5+ and Haiku 4.5 models, with a narrower Bedrock list.
