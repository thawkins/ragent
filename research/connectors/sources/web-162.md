Claude Desktop has three MCP configuration paths: packaged .mcpb extensions via Settings → Extensions (no JSON/Node), remote HTTPS servers via Settings → Connectors → Add custom connector (Team/Enterprise owners add under Organization settings; free accounts are limited to one connector), and local stdio servers via claude_desktop_config.json at ~/Library/Application Support/Claude/ on macOS or %APPDATA%\Claude\ on Windows, which requires Node.js/npx and a full restart. Troubleshooting should start with logs (~/Library/Logs/Claude or %APPDATA%\Claude\logs; mcp.log and per-server mcp-server-NAME.log), then manually running the server command, using absolute paths, and fixing ${APPDATA}/ENOENT via env. A known open Windows MSIX bug (anthropics/claude-code issue #26073, filed February 2026) silently ignores configs written to %APPDATA%\Claude\claude_desktop_config.json because the app reads a virtualized path under %LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\. Remote URLs cannot go directly in the config, though a local bridge like mcp-remote can connect hosted servers such as MESA (which requires Node.js 20.1.0+); Claude Code uses its own claude mcp add and does not read the desktop config. Servers run with the user account’s permissions, credentials in the config are plaintext, and Anthropic warns malicious MCP servers may hide instructions.
