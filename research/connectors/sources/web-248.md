AI Hub’s Part 2 guide explains how to create custom MCP servers inside IRIS during the early-access preview (explicitly not for production), contrasting them with preconfigured developer MCP servers such as Thomas Dyar’s separate iris-agentic-dev project. The architecture routes MCP clients through the iris-mcp-server binary to a `%AI.MCP.Service` dispatch class, configured with a `SPECIFICATION` parameter pointing to tools/toolsets extending `%AI.Tool` or `%AI.ToolSet`, which then reach ObjectScript classes that access IRIS databases, productions, or statuses. Setup involves creating an MCP web application (e.g., endpoint `/mcp/sample`, or Type 18 via `Security.Applications`) and configuring `iris-mcp-server` with a `config.toml` `[[iris]]` block—gateway-privileged credentials like `CSPSystem`/`SuperUser`, superserver port default `1972`, and endpoints—plus an `[mcp]` block for `stdio` or `http` (HTTP uses a separate port such as `8080`). Stdio clients run `/usr/irissys/bin/iris-mcp-server -c config_stdio.toml run` on the same machine/container, while HTTP clients keep `iris-mcp-server -c config_http.toml run` running and connect to URLs like `http://localhost:8080/mcp/sample`; authentication can be set in the web app, endpoint credentials/bearer token, or HTTP headers (Basic base64 or Bearer), with sample code in the `ai-hub-dev-template` on Open Exchange.
